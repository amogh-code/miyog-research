# The Trinity (high-level)

The Creator, Destroyer and Sustainer are fixed computational roles in one program. They are not agents or language models.

1. **Creator.** It proposes candidate equations between terms. Some come from earlier knowledge (consequences of held laws, regularities noticed during testing) and some are written at random.
2. **Destroyer.** It tests each candidate on many inputs through the trusted core. One disagreement refutes the candidate. Too little defined evidence leaves it *inconclusive*. Running out of computation leaves it *exhausted*, which is never counted as a refutation.
3. **Sustainer.** It admits survivors. A law that follows from what is already held is recorded as derived; otherwise it is held. On one formal world it requests a proof that an independent checker verifies. When a held law falls, the claims that rested on it are re-derived or re-tested.
4. **Trusted core and referee.** Every event is written to an append-only record. A law's status is computed from that record alone. No Trinity component can raise a law's standing by asserting it.

The paper (Section 4.3) has the detailed diagram and worked examples.
